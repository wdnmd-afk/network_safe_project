# API 功能级授权

## 场景目标

通过固定管理操作请求观察功能级授权缺失与服务端策略校验的差异。

本实验只使用固定案例 `privileged-operation-request`，普通用户请求管理员专属操作（如查看全量订单、修改他人角色），用两步决策对比漏洞版与修复版的后端判定、学习信号和统一事件日志。

本实验正在按 LT-021 接入专用两步决策交互链路（身份角色校验策略 → 操作处置决策），评估请求只接受固定 `scenarioKey` 和有序 `decisions` 决策路径。完成自动化验证前，元数据保持 `in-progress`。

## 前置条件

- 本机前端与后端服务已启动。
- 使用本项目本机演示账号登录。
- 不需要外部目标、第三方服务、真实凭据或真实业务数据。

## 使用方式

1. 访问 `/labs/api/functional-authorization/vuln`。
2. 第一步选择身份角色校验策略，第二步选择操作处置方式。
3. 载入推荐路径观察越权操作被接受。
4. 切换到 `/labs/api/functional-authorization/fixed`，观察越权操作被服务端功能级授权阻断。
5. 选择“管理员身份校验通过后放行”验证正常管理流程仍可继续。
6. 在实验详情或账户中心复盘统一事件日志。

## 安全边界

- 只使用固定虚构用户与管理操作枚举，不修改真实账户、角色或权限。
- 页面和 API 只接受本实验声明的固定 scenarioKey 与决策 optionKey。
- 未知 key 会被脱敏阻断，不写入原始输入或外部目标信息。

该实验仅提供本机受控固定场景和只读验证，不允许扩展为通用攻击工具。
