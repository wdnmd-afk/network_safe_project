# 凭据填充修复说明

## 根因

认证只判断单次口令结果且没有设备、速率和泄露凭据风险关联。

## 修复策略（两步决策）

- 第 1 步建立跨请求设备指纹、速率和泄露凭据关联，识别高风险登录批次。
- 第 2 步对高风险批次施加自适应挑战或阻断：
  - 防御拦截路径产生 `auth-credential-stuffing-defense-blocked`。
  - 正常登录路径（挑战通过后放行）产生 `auth-credential-stuffing-normal-verified`，证明修复不破坏正常业务。
- 未知 `scenarioKey` 或未登记决策 `optionKey` 必须脱敏阻断且不回显原始值。
- 事件日志只记录固定 case key、决策路径信号、结果计数和后端决策。

## 生产补充

真实生产环境还需要结合速率限制、泄露凭据库比对、设备与行为风控、多因素认证、异常登录告警和账号恢复流程实施分层防护；本实验结果不能替代生产安全评估。
