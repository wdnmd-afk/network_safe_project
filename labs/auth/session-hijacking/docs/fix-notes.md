# 会话劫持修复说明

本实验已在 LT-009 专用化为两步决策交互（上下文绑定策略 → 会话处置决策）。

## 根因

会话标识长期有效且没有轮换、设备上下文或高风险动作再验证。

## 修复策略

- 步骤一“绑定设备上下文并启用会话轮换”后，异地复用的会话摘要被识别并进入处置路径。
- 步骤二“防御阻断被复用会话”产生 `auth-session-hijacking-defense-blocked`，拦截被复用会话。
- 步骤二“再认证通过后放行正常会话”产生 `auth-session-hijacking-normal-verified`，验证修复后正常会话仍可继续。
- 未知 `scenarioKey` 或决策 `optionKey` 必须阻断且不回显原始值。
- 事件日志只记录固定 key、决策路径信号、结果计数和后端决策。

## 生产补充

真实生产环境还需要结合安全 Cookie 属性、会话轮换、设备上下文校验、高风险动作再认证和应急响应体系实施分层防护；本实验结果不能替代生产安全评估。
