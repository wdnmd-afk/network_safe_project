# OAuth 漏洞修复说明

## 根因

授权响应没有与原始客户端、回调地址和请求上下文严格绑定。

## 修复策略（两步专用状态机）

- 第 1 步授权绑定策略：选择“绑定回调地址、state 与 PKCE”，把授权请求与原始客户端上下文严格关联。
- 第 2 步授权响应决策：
  - “防御阻断被篡改授权响应”出现 `auth-oauth-defense-blocked`，验证防御路径。
  - “校验通过后放行正常授权”出现 `auth-oauth-normal-verified`，验证修复后正常授权码流程仍可继续。
- 未知 `scenarioKey` 或 `optionKey` 必须脱敏阻断且不回显原始值。
- 事件日志只记录固定 key、决策路径信号、后端决策和结果计数。

## 生产补充

真实生产环境还需要结合精确回调地址允许列表、nonce、最小 scope、令牌绑定、资产、身份和应急响应体系实施分层防护；本实验结果不能替代生产安全评估。
