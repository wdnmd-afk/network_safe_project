# 点击劫持

## 场景目标

通过固定嵌入式审批界面对比缺少框架限制与启用防嵌入策略的差异。

本实验只使用固定案例 `embedded-approval-overlay`，用于观察页面允许被任意来源嵌入且敏感动作缺少二次确认，并对比漏洞版与修复版的后端判定、学习信号和统一事件日志。

## 前置条件

- 本机前端与后端服务已启动。
- 使用本项目本机演示账号登录。
- 不需要外部目标、第三方服务、真实凭据或真实业务数据。

## 使用方式

1. 访问 `/labs/web/clickjacking/vuln`。
2. 沿风险路径依次选择“允许任意来源嵌入”和“无二次确认直接执行”，观察风险被接受。
3. 切换到 `/labs/web/clickjacking/fixed`，沿防御路径选择“启用 CSP frame-ancestors”和“防御拦截被劫持动作”，观察动作被阻断。
4. 在修复版沿正常路径选择“要求明确的用户确认”，确认正常受控审批流程仍可继续。
5. 在实验详情或账户中心复盘统一事件日志。

本实验为专用两步决策交互（框架策略 → 敏感动作确认），由第二版共享状态机驱动，页面只提供固定决策按钮，不接受任意输入。

## 安全边界

- 只处理固定本机 Web 教学场景，不生成可用于外部站点的攻击载荷。
- 页面和 API 只接受共享目录中声明的 scenarioKey 与 controlKey。
- 未知 key 会被脱敏阻断，不写入原始输入或外部目标信息。

该实验仅提供本机受控固定场景和只读验证，不允许扩展为通用攻击工具。
