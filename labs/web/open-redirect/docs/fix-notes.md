# 开放重定向修复说明

## 根因

服务端直接信任跳转目标且没有规范化与允许列表。

## 修复策略（两步决策）

- 第一步“跳转目标来源”：启用站内相对路径约束与目标允许列表后，外部输入控制的目标不再被直接信任（`web-open-redirect-target-restricted`）。
- 第二步“重定向决策”：
  - 防御拦截路径拦截未受信任跳转，返回 `web-open-redirect-defense-blocked`。
  - 正常跳转路径重定向到已校验的站内相对路径，返回 `web-open-redirect-normal-verified`，证明修复后正常业务仍可继续。
- 未知 `scenarioKey` 或未登记决策 `optionKey` 必须脱敏阻断且不回显原始值。
- 事件日志只记录固定案例 key、决策路径信号、结果计数和后端决策。

## 生产补充

真实生产环境还需要结合资产、身份、网络、终端、供应商和应急响应体系实施分层防护；本实验结果不能替代生产安全评估。
