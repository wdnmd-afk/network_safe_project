# 修复说明

## 根因

高风险交易的确认权完全交给浏览器渲染层。浏览器显示的收款方与金额只是客户端呈现结果，一旦该上下文不可信，用户看到的内容与服务端实际将要执行的内容就可能不同；如果交易又缺少独立签名，就没有任何证据能把用户的确认绑定到服务端记录的具体交易内容上。

## 固定修复策略

- 以服务端记录为交易内容基准，不把浏览器渲染结果当作可信来源。
- 增加带外确认通道，在浏览器上下文之外复核收款方与金额。
- 要求独立交易签名，把用户确认绑定到具体交易内容而不是会话。
- 三方视图任一不一致即返回 `client-mitb-defense-blocked`。
- 三方一致且已签名时返回 `client-mitb-normal-verified`，证明受信路径校验不阻断正常业务。
- 未登记 scenarioKey / optionKey、不完整路径和终止后追加决策统一脱敏阻断。
- 事件日志只记录固定 key、三项计数、步数、终止结果和 signal。

本实验不发起真实支付、转账、扣款、撤销或风控动作，也不实现、演示或描述任何浏览器内篡改能力。
