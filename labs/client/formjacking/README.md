# Formjacking

## 场景目标

通过固定结账页提交摘要的两步决策，观察脚本篡改与表单目标校验的差异。

本实验已在 LT-016 专用化为两步决策模拟，使用固定案例 `synthetic-checkout-target-change`：第 1 步选择第三方脚本信任策略，第 2 步选择表单提交目标处置方式，对比漏洞版与修复版的后端判定、学习信号和统一事件日志。

## 前置条件

- 本机前端与后端服务已启动。
- 使用本项目本机演示账号登录。
- 不需要外部目标、第三方服务、真实凭据或真实业务数据。

## 使用方式

1. 访问 `/labs/client/formjacking/vuln`，载入推荐路径观察风险被接受。
2. 切换到 `/labs/client/formjacking/fixed`，运行推荐（防御拦截）路径观察被篡改提交被阻断。
3. 在修复版选择“正常提交流程”，确认第一方目标校验通过后正常结账仍可继续。
4. 在实验详情或账户中心复盘统一事件日志。

## 安全边界

- 只使用固定浏览器行为案例，不注入真实页面、不采集表单数据。
- 页面和 API 只接受本实验声明的固定 scenarioKey 与决策 optionKey。
- 未知 key 会被脱敏阻断，不写入原始输入或外部目标信息。

该实验仅提供本机受控固定场景和只读验证，不允许扩展为通用攻击工具。
