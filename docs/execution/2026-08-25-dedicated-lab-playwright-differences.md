# LT-029 专用实验页面差异验证执行文档

## 1. 目标

为 `LT-006`～`LT-017` 已完成专用化、但尚未登记页面级证据的 7 个实验补充 Playwright 三向验证，证明漏洞版风险路径、修复版防御路径和修复后正常业务路径在真实页面上可区分、可运行、可观察。

目标实验固定为：

- `web.clickjacking`
- `web.open-redirect`
- `auth.credential-stuffing`
- `auth.session-hijacking`
- `auth.oauth`
- `client.formjacking`
- `malware.ransomware`

## 2. 范围

- 在现有 `packages/testing/tests/e2e/platform.spec.mjs` 增加上述 7 个专用实验的页面差异用例。
- 每个实验验证漏洞版推荐路径、修复版推荐路径和修复后正常流程路径。
- 断言专用页面标题、无自由文本输入、固定按钮和最终学习信号。
- 将 7 份元数据的 `verification.automation.playwright.enabled` 改为 `true`。
- 更新安全覆盖矩阵的 E6 证据和 Playwright 总数。
- 修正现有跨分类通用工作台用例，确保只覆盖仍在 `guidedScenarioCatalog` 中的场景。

不修改实验服务端状态机、业务字段、API 契约或页面功能，不增加新的攻击输入能力。

## 3. 操作步骤

1. 核对 7 个专用页面的标题、固定按钮、状态面板和学习信号。
2. 抽取 Playwright 登录与专用实验三向对照辅助逻辑。
3. 为 7 个实验分别声明可独立定位失败原因的页面差异用例。
4. 调整跨分类通用工作台代表清单，移除已经专用化的场景。
5. 启用 7 份元数据中的 Playwright 证据并更新覆盖矩阵统计。
6. 运行目标 Playwright、测试基础设施检查和根级门禁。
7. 回填验证结果并完成任务状态。

## 4. 实施建议

- 使用页面已经公开的标题、按钮和学习信号作为断言，不依赖内部组件状态。
- 每个实验单独生成测试标题，避免一个长循环失败后无法定位具体主题。
- 漏洞版只运行固定推荐风险路径；修复版同时验证阻断路径和正常业务路径。
- 保持 `malware.ransomware` 的 case-study 安全边界，不提供样本、文件操作或攻击脚本。

## 5. 潜在风险分析

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 旧通用用例继续访问已专用化页面 | 按通用工作台控件断言导致误报 | 通用清单只保留仍在共享目录中的场景 |
| 7 个实验放在单个测试循环 | 失败定位不清且单测试超时 | 按实验生成独立 Playwright 用例 |
| 只验证漏洞版与修复版阻断 | 无法证明修复后正常业务仍可继续 | 每个修复版都运行正常流程按钮并断言正常信号 |
| 元数据提前声明 E6 | 证据与实际用例不一致 | 用例通过后统一回填元数据和覆盖矩阵 |
| 页面验证越过安全边界 | 形成真实攻击操作 | 仅登录本机演示账号、点击固定按钮、断言固定摘要 |

## 6. 优化方案

- 复用一个专用实验对照辅助函数，统一登录、导航、运行和信号断言。
- 测试数据以结构化数组登记，后续新增专用实验可复用同一模式。
- 覆盖矩阵继续使用 E6 表示真实页面级差异证据，不把 API 或只读脚本误算为 Playwright。

## 7. 验证方式

- `pnpm --filter @network-safe/testing test`
- `pnpm --filter @network-safe/testing e2e --grep "专用实验页面差异"`
- `pnpm verify`
- `git diff --check`

本任务明确要求 Playwright 页面证据，用户已要求完成 `LT-027`～`LT-030`，因此上述目标 E2E 与根级门禁属于本轮完成条件。生产构建不在本任务范围。

## 8. 完成条件

- 7 个专用实验均具有风险、防御和正常三向页面断言。
- 页面测试不接受真实目标、凭据、URL、脚本、样本或自由正文。
- 通用工作台跨分类用例不再包含已专用化场景。
- 7 份元数据与覆盖矩阵准确登记 E6，统计与真实启用证据一致。
- 目标 Playwright 和根级门禁通过并回填证据。
