# LT-028 路由与元数据入口一致性检查执行文档

## 1. 目标

为全部实验变体建立元数据 `entrypoints` 与前端路由的一致性检查，并纳入根级 `verify` 门禁，避免实验入口配置存在但页面路由不可达。

## 2. 范围

- 扫描 `labs/**/meta.json` 中启用变体及 Web 入口。
- 读取 `apps/web/src/router/routes.ts` 的实验路由定义。
- 校验每个启用变体具有实验内唯一入口键和可匹配的全局唯一 Web 路径。
- 校验入口声明的变体与 `variants[].key` 一致。
- 将只读检查接入根级 `verify`。

不修改实验业务行为，不调用实验 API，不连接数据库或外部目标。

## 3. 操作步骤

1. 盘点元数据入口结构和现有专用、通用路由模式。
2. 实现只读入口一致性验证器。
3. 覆盖静态专用路由和通用参数路由。
4. 增加确定性测试与错误信息。
5. 接入根级 `verify`。
6. 更新长期目标、TODO 和完成进度。
7. 经用户授权后执行专项检查与 `pnpm verify`，通过后收口。

## 4. 实施建议

- 复用共享元数据解析与校验逻辑，不重复实现字段猜测。
- 使用结构化路由匹配，不通过仅搜索字符串判断入口存在。
- 错误信息包含实验 ID、变体和具体入口路径，便于定位。

## 5. 潜在风险

- 动态路由可能被错误判定为缺失，需要按 Vue Router 参数语义匹配。
- API、脚本和文档入口不是浏览器路由，本切片不混入 Web 可达性结论。
- 现有历史元数据可能暴露不一致，发现后应逐项确认真实契约，不做猜测式兼容。

## 6. 优化方案

- 验证器输出总实验数、启用变体数、已匹配入口数和错误列表。
- 后续可在该结构上扩展 API 路由和脚本文件存在性检查。

## 7. 验证方式

- 专项只读验证器。
- 对验证器执行正常、缺失入口、重复入口和变体不一致测试。
- `pnpm verify`。
- `git diff --check`。

用户已明确要求完成 `LT-027`～`LT-030`，因此本轮执行专项检查、根级门禁和静态差异检查。

## 8. 完成条件

- 所有启用实验变体均能匹配准确的 Web 入口。
- 动态和专用路由均按真实路由语义处理。
- 检查已纳入根级 `verify`。
- 专项验证与 `pnpm verify` 通过并回填证据。
