## 2. 规划原则

- 只使用固定虚构样例与确定性状态机，不生成、存储或校验真实密钥、口令、token 或证书私钥。
- 复用现有口令哈希（`apps/server/src/services/password.ts`）、JWT（`jwt-lab.ts`）与会话（`session-token.ts`）实现作为讲解锚点，不新建平行密码系统。
- 优先补应用侧最常见、最可判定的密码学误用：口令哈希策略、不安全随机数、密钥生命周期、秘密泄露。
- 高深度或高误导风险主题（TLS 证书链、加密传输、数字签名）先以固定案例状态机表达，不做真实加解密或握手。
- 首批沿用 clickjacking～oauth 建立的第二版专用化样板（`interactive`），或以 `simulation` 表达纯状态观察。

## 5. 每个候选的固定模型与边界

### 5.1 口令哈希策略

- 固定案例：同一口令分别用弱策略（明文/单轮 MD5/无盐）与强策略（scrypt+盐+足够成本）存储的固定摘要对比。
- 两步决策：算法选择（弱哈希 vs 加盐 KDF）→ 处置（弱存储接受 / 阻断并要求升级 / 正常强存储放行）。
- 边界：只展示固定哈希字符串样例，不接收真实口令，不落库，不校验真实账户。

### 5.2 不安全随机数与 token 熵

- 固定案例：可预测 token 序列（时间戳/自增/弱 PRNG）与安全随机 token 的固定熵摘要对比。
- 状态机：使用弱随机接受 → 识别低熵/可预测模式 → 切换安全随机源验证。
- 边界：只使用固定预生成样例与熵统计摘要，不生成真实会话 token，不接入真实认证。
- 实施状态：`LT-023` 已完成 D3 专用模拟、统一事件摘要、只读验证和根级验证收口。

### 5.3 密钥生命周期

- 固定案例：长期不轮换、无版本、无吊销的密钥台账 vs 具备生成/轮换/吊销/版本的台账。
- 两步决策：密钥台账策略（静态长期 vs 生命周期管理）→ 处置（继续使用泄露密钥 / 阻断并轮换 / 正常受控使用）。
- 边界：只使用固定虚构密钥 ID 与状态枚举，不含真实密钥材料，不做真实加解密。

### 5.4 秘密泄露扫描

- 固定案例：固定配置片段、日志行、源码片段与构建产物清单中植入的虚构秘密标记。
- 状态机：无扫描直接发布接受 → 命中固定秘密模式 → 移除并改用注入后正常发布。
- 边界：只扫描固定内嵌样例字符串，不读取真实 `.env`、真实凭据或真实仓库历史。
- LT-038 实现 ID 为 `crypto.secret-lifecycle-audit`，将固定秘密标记与 `virtual-key-v1/v2` 生命周期台账合并为两步 D3 模拟。
- 当前服务/API、页面、标准目录和只读验证入口已落地，专项、根级门禁和代表性 Playwright 已通过，元数据已推进 `ready`。

## 8. 安全边界总纲

- 只使用固定虚构样例、预生成摘要与状态枚举，不生成、存储、校验或传输真实密钥、口令、token 或证书私钥。
- 不实现真实加解密、真实签名验签、真实 TLS 握手或真实随机源接入认证链路。
- API 与页面只接受注册过的固定 key，未知 key 脱敏阻断且不回显原始输入。
- 事件日志只记录固定 key、步骤、决策、信号和安全摘要，绝不记录任何疑似秘密的原始值。
- 不提供可迁移到外部目标的密钥爆破、哈希破解、证书伪造或秘密外泄工具。
