## 1. 文档定位

本文档回答云原生与 IaC 方向「先做什么、用什么固定模型、边界在哪」，对应长期目标 `SECURITY-COVERAGE-LONG-TERM-GOAL.md` 第 9.5 节。

本文档只做规划，不包含运行时代码。每个实验进入实现前仍须单独编写执行文档。

## 2. 首批候选切片

`LT-014` 确认的四项首批候选，按学习价值与边界清晰度排序：

| 顺序 | 实验 | 建议模式 | 结构性价值 |
|---|---|---|---|
| 1 | 云 IAM 策略最小权限审计 | `simulation` | 固定策略快照对比，补主体/资源/动作/条件四要素与通配符风险（`LT-026` 实现切片） |
| 2 | 对象存储公开暴露 | `simulation` | 固定 bucket 策略与 ACL 组合，补公开读写与审计缺失 |

## 3. 分类归属决策

`LT-014` 把「分类注册」列为前置确认项，未做结论。`LT-026` 开工时确认如下：

- 首批四项**不新增 `cloud` 分类**，统一归入现有 `infrastructure` 分类。
- 理由：`infrastructure.cloud-security`、`infrastructure.container-escape`、`infrastructure.iot` 已经承载云与容器主题；另立 `cloud` 分类会把云相关实验拆散到两个分类，破坏列表分组、覆盖矩阵分节和统计口径。
- 该决策可逆：若后续云原生实验增长到足以独立成节（例如超过 5 项），再评估拆分并同步分类注册、覆盖矩阵与计数断言。

## 4. 与既有实验的复用关系

- `infrastructure.cloud-security`（引导式 D2）保持现状，不因新增专用实验而下线；其长期动作仍是补存储与网络边界视角。
- `infrastructure.misconfiguration`（专用）已建立固定配置审计范式，新增实验复用其「固定清单 + 语义枚举 + 只读判定」模式，不复制其字段结构。
- 授权类判定不重造：对象级与功能级授权继续由 `auth.idor` 与 `api.functional-authorization` 承载，云 IAM 实验只聚焦策略文档本身的最小权限评估。

## 5. 固定模型约定

所有云原生实验共同遵守：

- 策略、YAML 与配置片段只使用虚构账号 ID、虚构 ARN 风格标识和虚构资源名，不含真实云账号、租户、区域端点或密钥。
- 主体、动作、资源、条件只使用预登记的语义枚举，服务端基于固定集合做确定性计数，不解析真实云策略语言，不调用任何云 SDK。
- 评估 API 只接受已注册 `scenarioKey` 与有序 `decisions`，不接受策略正文、JSON、YAML、ARN、账号、密钥或自由文本。
- 未知 key 统一脱敏阻断，不回显原始输入，也不写入事件日志。

## 6. 安全边界（全方向共同）

- 不连接、认证或修改任何真实云账户、订阅、项目、集群、IaC 后端或对象存储。
- 不调用 AWS/Azure/GCP/Kubernetes API、CLI、SDK 或 Terraform 可执行文件。
- 不读取本机云凭据文件、kubeconfig、环境变量或 CI 密钥。
- 不启动容器、Pod、虚拟机或任何真实工作负载。
- 不生成可直接用于真实环境的提权策略、绕过清单或攻击脚本。
- 不提供 `exploit.py`。

## 8. 验证方式

- 每个实验保留独立只读 `verify.ts`，反向核对元数据、路由顺序、固定 key、文档与禁用能力。
- 纳入覆盖矩阵并保持模式与深度一致。
- 最小收口门禁为专项只读验证加根级 `pnpm verify`；build、smoke、数据库集成与 Playwright 按需另行授权。
